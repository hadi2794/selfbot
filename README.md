# سلف‌بات تلگرام (Telethon)

## ساختار پروژه (ماژولار)

کد از یک فایل تک‌تکه به این ساختار تقسیم شده؛ نقطه‌ی اجرا هنوز `main.py`
است و هیچ متغیر محیطی یا دستوری تغییر نکرده:

```
main.py                       نقطه‌ی اجرا: wiring + client.run_until_disconnected
bot/
  config.py                   همه‌ی تنظیمات از .env (تنها جایی که os.getenv صدا زده می‌شه)
  runtime.py                  نمونه‌ی TelegramClient + سشن HTTP مشترک + SELF_ID
  utils.py                    ساخت الگوی regex دستورات (pat)
  calc.py                     ماشین‌حساب امن (.حساب)
  fonts.py                    نگاشت‌های فونت پیام
  clock.py                    استایل‌های ساعت زنده + تسک پس‌زمینه‌ی آپدیت پروفایل
  ai.py                       هسته‌ی هوش مصنوعی: wrapper روی APIِ سازگار با OpenAI (.پرسش/.خلاصه/منشی)
  db/                         اتصال PostgreSQL (SQLAlchemy 2.x async + psycopg 3) + ORM models
    engine.py, models.py, bootstrap.py
  repositories/                Repository/Database Layer - تنها لایه‌ای که SQL می‌زنه
    notes_repo.py, assistant_repo.py, autopost_repo.py,
    font_repo.py, clock_repo.py, stats_repo.py, scheduler_repo.py,
    group_guard_repo.py
  storage/                    آداپتورهای async روی Repository Layer + نگه‌داریِ state درون‌حافظه‌ای
    notes_store.py, font_store.py, assistant_store.py,
    autopost_store.py, clock_store.py, stats_store.py, scheduler_store.py,
    group_guard_store.py
  handlers/                   هر فایل یک دسته از دستورات (همون شماره‌گذاری راهنمای قبلی)
    general.py, tools.py, notes.py, messages.py, fun.py, font.py,
    profile.py, assistant.py, ai.py, admin.py, groupguard.py, backup.py,
    autopost.py, stats.py, scheduler.py, help.py, panel.py
migrations/                   Alembic migrations (schema PostgreSQL)
scripts/
  migrate_json_to_postgres.py  انتقال یک‌بارِ JSONهای قدیمی به PostgreSQL (با بکاپ و شمارش قبل/بعد)
```

⚠️ **از این نسخه به بعد، منبع اصلیِ داده‌های دائمی (یادداشت‌ها/منشی/ارسال‌خودکار/
آمار/ساعت زنده) PostgreSQL است، نه فایل JSON.** فایل‌های JSON قدیمی فقط برای
اسکریپت یک‌بارِ migration و برای Import/Export دستیِ بکاپ (`.پشتیبان تنظیمات` /
`.بازیابی`) استفاده می‌شن؛ برای جزئیات کامل به بخش «PostgreSQL روی Railway»
پایین‌تر مراجعه کن.

افزودن یک دستور جدید یعنی فقط باز کردن فایل `handlers/` مربوطه (یا ساختن
یک فایل جدید و اضافه‌کردنش به `handlers/__init__.py`) - نیازی به دست‌زدن
به بقیه‌ی پروژه نیست.

## نصب روی Railway (روش اصلی)

نکته مهم: چون سرورهای Railway ترمینال تعاملی برای وارد کردن کد تایید تلگرام
ندارن، باید مرحله لاگین (گرفتن Session String) رو **اول روی سیستم خودت** انجام
بدی، بعد فقط همون رشته رو به Railway بدی.

**۱) گرفتن Session String روی سیستم خودت (یک‌بار، قبل از دیپلوی)**
```
pip install telethon python-dotenv
python generate_session.py
```
(قبلش API_ID و API_HASH رو توی یک فایل `.env` کنار `generate_session.py` بذار،
یا مستقیم داخل خود اسکریپت جایگزین کن.) شماره‌تلفن و کدی که تلگرام می‌فرسته رو
وارد کن؛ در آخر یک رشته طولانی چاپ می‌شه — همینو نگه دار.

**۲) ساختن دیتابیس PostgreSQL روی Railway**

توی همون پروژه‌ی Railway → **New → Database → Add PostgreSQL**. Railway خودش
یک متغیر محیطی `DATABASE_URL` می‌سازه و به سرویسِ بات وصلش می‌کنه (اگه از
Reference Variables استفاده کنی؛ وگرنه مقدارش رو از تب Variables دیتابیس کپی
کن و دستی توی سرویسِ بات هم ست کن).

**۳) دیپلوی روی Railway**

از طریق گیت‌هاب (پیشنهادی):
1. این پوشه (`main.py`, `requirements.txt`, `Procfile`, `railway.json`,
   `alembic.ini`, `migrations/`) رو به یک ریپوی گیت‌هاب پوش کن.
2. توی Railway → **New Project → Deploy from GitHub repo** → ریپو رو انتخاب کن.
3. Railway به‌خاطر `requirements.txt` خودش تشخیص می‌ده پروژه پایتونیه و با
   Nixpacks بیلدش می‌کنه. `railway.json`/`Procfile` دستور اجرا رو خودشون
   مشخص کردن:
   ```
   alembic upgrade head && python main.py
   ```
   یعنی هر دیپلوی/ری‌استارت، اول schema دیتابیس رو به آخرین migration
   می‌رسونه (بی‌خطر و idempotent - Alembic خودش می‌فهمه چی از قبل اجرا شده)
   و بعد بات رو روشن می‌کنه؛ نیازی به اجرای دستیِ جدا نیست.

یا از طریق CLI:
```
npm i -g @railway/cli
railway login
railway init
railway up
```

**۴) تنظیم متغیرهای محیطی**

توی داشبورد پروژه → تب **Variables** این‌ها رو اضافه کن:
- `API_ID`
- `API_HASH`
- `SESSION_STRING` (همونی که مرحله ۱ گرفتی)
- `DATABASE_URL` (اگه با Reference Variable از مرحله ۲ خودکار وصل نشده)
- اختیاری: `PREFIX`, `TIMEZONE_OFFSET`, `CLOCK_INTERVAL`, `DB_POOL_SIZE`, `DB_MAX_OVERFLOW`
- اختیاری: `BOT_TOKEN` — برای فعال‌کردن پنل دکمه‌ای `.پنل` (پایین‌تر توضیح داده شده)
- اختیاری: `AI_API_KEY` (و `AI_API_BASE`/`AI_MODEL`) — برای فعال‌کردنِ `.پرسش`/`.خلاصه`/منشیِ هوشمند (پایین‌تر توضیح داده شده)

**پنل دکمه‌ای (`.پنل`)**

تلگرام دکمه‌های شیشه‌ای (inline keyboard) رو فقط برای پیام‌های ارسالی از طرف
یه بات واقعی نمایش می‌ده، نه پیام‌های اکانت شخصی/سلف‌بات. برای همین دستور
`.پنل` از یه بات کمکیِ جدا (نه اکانت خودت) برای نمایش منوی دکمه‌ای استفاده
می‌کنه:

۱. توی تلگرام برو پیش [@BotFather](https://t.me/BotFather)، با `/newbot` یه
   بات جدید بساز و توکنش رو بگیر.
۲. **حالت Inline رو فعال کن:** توی @BotFather بزن `/mybots` → بات موردنظر →
   **Bot Settings** → **Inline Mode** → **Turn on**. (این قدم لازمه تا پنل
   بتونه مستقیم توی همون چتی که `.پنل` می‌زنی نمایش داده بشه؛ بدون این قدم،
   فقط یه لینکِ باز کردنِ چت خصوصیِ بات کمکی برات میاد.)
۳. توکن رو توی `.env` (یا Variables روی Railway) با نام `BOT_TOKEN` ست کن.
۴. سلف‌بات رو (ری‌)استارت کن — لاگ `🤖 بات کمکیِ پنل به @... وصل شد` باید
   بیاد.
۵. توی هر چتی (خصوصی، گروه، Saved Messages، ...) که سلف‌بات فعاله، دستور
   `.پنل` رو بزن؛ پنلِ دکمه‌ای همون‌جا (با برچسبِ «via @نام‌بات») ظاهر می‌شه و
   پیامِ خودِ دستور پاک می‌شه. اجرای واقعیِ دستورها (مثل `.حساب` یا
   `.یادداشت`) همچنان با اکانت خودت و توی همون چتی که لازم داری انجام
   می‌شه — بات کمکی فقط برای نمایش/ناوبریِ راهنماست، دستوری اجرا نمی‌کنه.

اگه `BOT_TOKEN` رو ست نکنی، `.پنل` فقط یه پیام راهنما می‌ده و بقیه‌ی
دستورات سلف‌بات مثل همیشه عادی کار می‌کنن. اگه `BOT_TOKEN` رو ست کنی ولی
Inline Mode رو فعال نکنی، `.پنل` به‌جای نمایش مستقیم، همون لینکِ باز کردنِ
چتِ خصوصیِ بات کمکی رو برات می‌فرسته.

بعد از ست‌کردن متغیرها، Railway خودش سرویس رو ری‌استارت می‌کنه و بات روشن می‌شه.
چون Railway (برخلاف Replit رایگان) پراسس رو به‌خاطر بی‌فعالیتی نمی‌خوابونه،
هیچ تریک keep-alive یا وب‌سروری لازم نیست.

### انتقالِ (Migration) داده‌های قدیمیِ JSON به PostgreSQL

اگه از قبل با نسخه‌ی JSON این پروژه استفاده می‌کردی و فایل‌های
`notes.json` / `autopost.json` / `assistant.json` / `font_state.json` /
`stats.json` رو داری، یک‌بار (بعد از `alembic upgrade head`) این رو اجرا کن:
```
python scripts/migrate_json_to_postgres.py
```
این اسکریپت قبل از هر کاری از فایل‌های JSON بکاپ می‌گیره، تعداد رکوردها رو
قبل/بعد از migration مقایسه می‌کنه، و اگه چیزی مطابقت نداشت با خطا متوقف
می‌شه بدون این‌که چیزی از PostgreSQL یا فایل‌های اصلی پاک بشه (idempotent -
می‌تونی چندبار اجراش کنی).

⚠️ **نکته‌ی قدیمی درباره‌ی Volume دیگه لازم نیست:** چون منبع اصلیِ داده حالا
PostgreSQL (که خودش دائمیه) هست، نیازی به وصل‌کردن Railway Volume برای
`notes.json` و مشابه‌هاش نیست.

## نصب روی Replit (روش جایگزین)

1. یک Repl جدید از نوع **Python** بساز و این ۴ فایل رو داخلش آپلود کن:
   `main.py`, `requirements.txt`, `generate_session.py`, `.env.example`
2. توی Shell ری‌پلیت بزن:
   ```
   pip install -r requirements.txt
   ```
3. توی تب **Secrets** (آیکون قفل) این مقادیر رو اضافه کن:
   - `API_ID`
   - `API_HASH`
   - `PREFIX` (اختیاری، پیش‌فرض `.`)
   - `TIMEZONE_OFFSET` (اختیاری، پیش‌فرض `3.5` برای تهران)
   - `CLOCK_INTERVAL` (اختیاری، پیش‌فرض `60` ثانیه)
4. یک‌بار دستور زیر رو اجرا کن تا لاگین کنی و Session String بگیری:
   ```
   python generate_session.py
   ```
   شماره‌تلفن و کد تاییدی که تلگرام می‌فرسته رو وارد کن. در انتها یک رشته طولانی
   چاپ می‌شه — همون رو هم به Secrets اضافه کن با نام `SESSION_STRING`.
5. حالا `main.py` رو اجرا کن (دکمه Run). دیگه لازم نیست دوباره لاگین کنی.

## نگه‌داشتن بات روشن روی Replit رایگان

Replit رایگان بعد از مدتی بی‌فعالیتی Repl رو خاموش می‌کنه. برای روشن نگه‌داشتنش
معمولاً یک وب‌سرور کوچک (Flask) اضافه می‌کنن و با سرویسی مثل UptimeRobot هر چند
دقیقه بهش پینگ می‌زنن. اگر خواستی همچین چیزی هم اضافه کنم بگو.

## استفاده

پیشوند پیش‌فرض `.` است. مثلاً بنویس `.راهنما` تا لیست کامل دستورات رو ببینی.

دستورها فارسی‌ان (مثل `.راهنما`, `.پینگ`, `.منشی`)، ولی نام‌های انگلیسیِ قدیمی
(`.help`, `.ping`, `.assistant`, …) هم برای سازگاری هنوز کار می‌کنن - هرکدوم
راحت‌تره همونو استفاده کن.

## ارسال خودکار متن به گروه

با `.ارسال‌خودکار` می‌تونی یه متن رو با فاصله‌ی زمانی دلخواه به یک یا چند گروه که
خودت انتخاب می‌کنی بفرستی. برای شروع:
```
.ارسال‌خودکار متن میو
.ارسال‌خودکار افزودن        (این دستور رو داخل خودِ گروه مقصد بفرست)
.ارسال‌خودکار فاصله 5
.ارسال‌خودکار روشن
```
برای دیدن وضعیت کامل کافیه فقط `.ارسال‌خودکار` رو بفرستی.

⚠️ فاصله‌های خیلی کم (زیر ۵ دقیقه) و پیام‌های تکراری، ریسک تشخیص به‌عنوان
اسپم توسط سیستم‌های خودکار تلگرام رو بالا می‌برن؛ سعی کن فاصله رو معقول نگه
داری و از این قابلیت فقط توی گروه‌های خودت استفاده کنی.

همین‌طور تنظیمات ارسال‌خودکار (مثل notes) در PostgreSQL ذخیره می‌شه، پس با
دیپلوی/ری‌استارت از دست نمی‌ره.

با `.آمار` هم می‌تونی هر وقت خواستی ببینی چندتا ارسال‌خودکار موفق/ناموفق بوده
(به بخش «📊 آمار سلف‌بات» پایین‌تر نگاه کن).

## زمان‌بندی و یادآوری

با `.زمان‌بند` می‌تونی یه متن رو برای زمانِ مشخصی توی همون چت زمان‌بندی کنی، و با
`.یادآوری` همون کار رو برای یه یادآوریِ شخصی که به Saved Messages می‌رسه. مثال:
```
.زمان‌بند 10m یادت نره جلسه رو چک کنی
.زمان‌بند 14:30 وقت ناهاره!
.یادآوری 2ساعت باشگاه
.یادآوری 2026-08-25 09:00 تولد سارا
```
فرمت‌های مجاز برای «زمان»:
- نسبی: `10m` `2h` `1d` `45s` یا فارسی `10دقیقه` `2ساعت` `1روز` `45ثانیه`
- ساعتِ امروز/فردا: `14:30` (اگه گذشته باشه، خودکار می‌ره برای فردا)
- تاریخ و ساعت کامل: `2026-08-25 14:30`

می‌تونی به‌جای تایپِ متن، روی یه پیام ریپلای کنی و فقط `.زمان‌بند 10m` یا
`.یادآوری 10m` رو بزنی.

برای دیدن لیست و لغوِ یک زمان‌بندی/یادآوری:
```
.زمان‌بند لیست
.زمان‌بند لغو 3
.یادآوری لیست
.یادآوری لغو 3
```
(عددِ جلوی «لغو» همون شناسه‌ایه که موقع ثبت یا توی لیست نشون داده می‌شه.)

کارهای زمان‌بندی‌شده هم مثل بقیه‌ی تنظیمات در PostgreSQL ذخیره می‌شن، پس با
ری‌استارت/ری‌دیپلوی از دست نمی‌رن - یه تسکِ پس‌زمینه هر ۱۵ ثانیه چک می‌کنه چیزی
سررسیده یا نه.

## منشی چت (پاسخ خودکار هوشمند)

با `.منشی` می‌تونی یه منشی بسازی که وقتی خودت واقعاً آفلاینی، خودکار به
پیام‌ها جواب بده - و وقتی برگردی (مثلاً گوشیت فعال بشه) خودش خاموش بشه. برای
شروع:
```
.منشی متن سلام 👋 فعلاً آنلاین نیستم، پیامتون رو دیدم و به‌زودی جواب می‌دم.
.منشی حالت منشن
.منشی تأخیر 3
```
همین! دیگه لازم نیست دستی روشن/خاموشش کنی - تشخیص آنلاین/آفلاین خودکاره (هر
۳۰ ثانیه سشن‌های فعال اکانتت رو چک می‌کنه: اگه سشن دیگه‌ای غیر از همین اسکریپت
به‌تازگی فعال بوده، یعنی خودت آنلاینی و منشی خاموش می‌مونه). اگه خواستی دستی
override کنی: `.منشی روشن` یا `.منشی خاموش` (توجه: با اولین فعالیت
واقعی‌ات دوباره خودکار اصلاح می‌شه).

⚠️ **درباره‌ی حالت‌ها:** پیش‌فرض `منشن` هست - یعنی فقط وقتی توی گروه تگ یا
ریپلای بشی جواب می‌ده (توی پیوی همیشه جواب می‌ده، چون پیوی ذاتاً خطاب به
خودته). حالت `خودکار` رو فقط زمانی روشن کن که واقعاً می‌خوای به **همه‌ی** پیام‌های
یه چت جواب بده، حتی بدون تگ - وگرنه توی گروه‌های شلوغ شبیه اسپم می‌شه.

به هر شخص فقط یک‌بار در هر نشست جواب داده می‌شه (نه به هر پیام)، تا اسپم نشه.
با `.منشی مستثنی` / `.منشی شامل` هم می‌تونی چت‌های خاص رو از
قانون کلی مستثنی یا همیشه‌فعال کنی. برای دیدن وضعیت کامل: `.منشی`.

**قفل دستی:** با `.منشی روشن` یا `.منشی خاموش` می‌تونی دستی روشن/خاموشش
کنی - و از اون لحظه، تشخیص خودکار آنلاین/آفلاین دیگه دست بهش نمی‌زنه (حتی اگه
واقعاً آفلاین بشی، خاموش می‌مونه؛ حتی اگه آنلاین بشی، روشن می‌مونه). برای
برگردوندن به حالت خودکار: `.منشی خودکار`.

**اتصالِ منشی به هوش مصنوعی (اختیاری):** به‌جای متنِ ثابتِ همیشگی، می‌تونی
بذاری هر پاسخ با هوش مصنوعی و بر اساس متنِ پیامِ ورودی تولید بشه:
```
.منشی هوش‌مصنوعی روشن
```
این کار نیازمندِ `AI_API_KEY` (بخش «هوش مصنوعی» پایین‌تر رو ببین) هست؛ اگه
کلید ست نباشه یا درخواست fail بشه، خودکار به همون متنِ ثابتِ `.منشی متن ...`
fallback می‌کنه (پس تنظیم‌کردنِ یه متنِ ثابت به‌عنوان پشتیبان همیشه توصیه
می‌شه). برگردوندن به متنِ ثابت: `.منشی هوش‌مصنوعی خاموش`.

⚠️ **فرقِ مهم با حالتِ متنِ ثابت:** توی حالتِ متنِ ثابت، منشی به هر نفر فقط
یک‌بار در هر نشست جواب می‌ده (تا اسپم نشه، چون همیشه همون یه متنِ تکراریه).
ولی توی حالتِ هوش‌مصنوعی، این محدودیت برداشته می‌شه و منشی به **تک‌تکِ
پیام‌ها** جواب می‌ده - چون هر پاسخ مخصوصِ همون پیامه، نه یه متنِ تکراری. این
یعنی توی چت‌های شلوغ ممکنه تعدادِ درخواستِ زیادی به سرویسِ AI بزنه (و هزینه/
مصرفِ اعتبار بالا بره)، پس بهتره یا از `.منشی مستثنی` برای چت‌های خیلی شلوغ
استفاده کنی، یا حالتِ پاسخ رو محدودتر (مثلاً `مستثنی`/`پیوی`) نگه داری.

هر پاسخِ تولیدشده با هوش مصنوعی، یه واترمارکِ خیلی کوچیک و محو در انتهاش داره
(به‌صورتِ اسپویلِ تلگرامی - یه تکه‌ی تار/بلور که تا لمس نشه باز نمی‌شه، پس
ظاهرِ کلیِ پیام رو خراب نمی‌کنه) تا اگه بعداً خواستی چک کنی کدوم پاسخ‌ها
خودکار/هوش‌مصنوعی بودن، مشخص باشه.

## هوش مصنوعی

دو دستورِ مستقل برای استفاده از یه مدل زبانی، به‌علاوه‌ی قابلیتِ اتصال به
منشی (بخش بالا). هر دو از یه هسته‌ی مشترک (`bot/ai.py`) استفاده می‌کنن که
یه wrapper سبک روی APIِ چت‌تکمیلیِ سازگار با OpenAI (`/chat/completions`) ه -
یعنی هم خودِ OpenAI جواب می‌ده، هم هر سرویسِ دیگه‌ای (مثلاً یه proxy یا مدلِ
اوپن‌سورسِ self-hosted) که همون فرمت رو پیاده کنه، فقط کافیه `AI_API_BASE`
رو عوض کنی.

**راه‌اندازی:** توی `.env` (یا Variables روی Railway) این‌ها رو ست کن:
```
AI_API_KEY=sk-...
# اختیاری:
AI_API_BASE=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
AI_MAX_TOKENS=600
```
اگه `AI_API_KEY` رو ست نکنی، `.پرسش`/`.خلاصه`/`.منشی هوش‌مصنوعی` فقط یه
پیامِ راهنما می‌دن و بقیه‌ی سلف‌بات مثل همیشه عادی کار می‌کنه.

ℹ️ **`.رونویسی`/`.متن‌به‌صوت` دیگه به `AI_API_KEY` نیازی ندارن** - این دو تا
جدا شدن و از سرویس‌های رایگان استفاده می‌کنن؛ توضیحش توی بخشِ «🔊 صوت و متن»
پایین‌تره. `AI_API_KEY` فقط برای `.پرسش`/`.خلاصه`/منشیِ‌هوشمند و برای
ترکیبِ اختیاریِ «رونویسی + سوال از AI» لازمه.

**`.پرسش`** - سوال از مدل، یا خلاصه/تحلیلِ یه پیام:
```
.پرسش پایتخت فرانسه کجاست؟
```
با ریپلای روی یه پیام:
```
.پرسش                     ← خلاصه/تحلیلِ همون پیام
.پرسش این پیام چی میگه؟    ← سوال درباره‌ی همون پیام (متنِ پیام به‌عنوان context)
```

**`.خلاصه`** - خلاصه‌ی N پیامِ آخرِ یه چتِ شلوغ:
```
.خلاصه
.خلاصه 100
```
پیش‌فرض ۵۰ پیامِ آخرِ همین چت رو جمع می‌کنه (سقفِ قابل‌تنظیم با
`AI_SUMMARY_MAX_MESSAGES`، پیش‌فرض ۳۰۰) و یه خلاصه‌ی کوتاه از موضوعاتِ اصلیِ
بحث برمی‌گردونه. برای چت‌های خیلی طولانی، بخشِ ابتدایی‌ترِ متن‌ها ممکنه به‌خاطرِ
سقفِ حجمِ ارسالی به مدل کنار گذاشته بشه (آخرین پیام‌ها اولویت دارن).

⚠️ **نکته:** این قابلیت پیام‌ها رو به یه سرویسِ بیرونی (OpenAI یا هر
endpoint‌ای که تنظیم کردی) ارسال می‌کنه - برای چت‌های حساس/خصوصی با احتیاط
استفاده کن.

## 🔊 صوت و متن

رونویسیِ ویس (Speech-to-Text) و ساختِ ویس از متن (Text-to-Speech) - **کاملاً
رایگان و بدونِ نیاز به `AI_API_KEY`**: رونویسی از موتورِ رایگانِ گوگل
(کتابخونه‌ی `SpeechRecognition`) و متن‌به‌صوت از `edge-tts` (همون موتورِ
Read Aloud مرورگرِ Microsoft Edge) استفاده می‌کنن - نه کلید می‌خوان، نه
هزینه‌ای دارن؛ فقط اتصال به اینترنت لازمه (و ffmpeg، که توی Dockerfile از
قبل نصبه).

**`.رونویسی`** - ریپلای روی یه پیامِ صوتی/ویس:
```
.رونویسی                 ← فقط متنِ رونویسی‌شده رو برمی‌گردونه
.رونویسی خلاصه‌ش کن       ← رونویسی می‌کنه و بعد همون متن رو به AI می‌ده
                            (این حالتِ دوم نیازمندِ AI_API_KEY هست)
```

**`.متن‌به‌صوت`** - متن رو به ویس تبدیل می‌کنه:
```
.متن‌به‌صوت سلام، حالت چطوره؟
```
یا با ریپلای روی یه پیامِ متنی (بدونِ نوشتنِ متن، همون پیام رو می‌خونه).

**تنظیمِ زبان/صدا (اختیاری):** پیش‌فرض روی فارسی (`fa-IR`) و یه صدای مردانه
تنظیم شده؛ اگه بخوای عوضش کنی:
```
STT_LANGUAGE=fa-IR
TTS_VOICE=fa-IR-FaridNeural   # صدای زنانه: fa-IR-DilaraNeural
```
برای دیدن لیستِ کاملِ صداهای edge-tts: `python -m edge_tts --list-voices`

⚠️ **نکته:** موتورِ رایگانِ رونویسیِ گوگل یه endpointِ رسمی/تجاری نیست
(همون سرویسِ آزمایشیِ رایگانیه که کتابخونه ازش استفاده می‌کنه) - برای
استفاده‌ی شخصی خوب کار می‌کنه ولی تحتِ محدودیتِ نرخِ درخواسته و SLA/تضمینی
نداره. اگه بعداً خواستی، همچنان می‌تونی با تغییرِ `bot/local_speech.py`
دوباره به یه سرویسِ AI پولی (مثلِ OpenAI Whisper/TTS، از طریقِ
`bot/ai.py`) برگردی.

## مدیریت گروه پیشرفته

سه تا قابلیتِ اضافه‌تر برای گروه‌ها، جدا از دستورهای پایه‌ی «مدیریت گروه»
(`.اخراج`/`.مسدود`/... که بالاتر توضیح داده شدن):

**فیلترلینک** - حذف خودکار پیام‌های حاویِ لینک از اعضای غیرادمین:
```
.فیلترلینک روشن
.فیلترلینک خاموش
.فیلترلینک وضعیت
```
وقتی روشنه، هر پیامی توی همون گروه که لینک (`http(s)://`, `www.`, `t.me/`,
`telegram.me/`) داشته باشه و فرستنده‌ش ادمین/سازنده‌ی گروه نباشه، خودکار حذف
می‌شه. خودتون و بقیه‌ی ادمین‌ها همیشه مستثنی‌اید. وضعیت به‌ازای هر گروه جدا
ذخیره می‌شه (توی PostgreSQL، پس با ری‌استارت از دست نمی‌ره).

**خوش‌آمد** - پیام خوش‌آمدگویی خودکار برای عضو جدیدِ گروه:
```
.خوش‌آمد متن سلام {نام} 👋 خوش اومدی به گروه!
.خوش‌آمد روشن
```
داخل متن می‌تونی از `{نام}` (اسمِ کاربر) یا `{منشن}` (تگِ واقعیِ کاربر که با
کلیک پروفایلش باز می‌شه) استفاده کنی. برای دیدن وضعیت/متنِ فعلی: `.خوش‌آمد`.

**برچسب‌همه** - تگ‌زدنِ همه‌ی اعضای گروه با یه دستور:
```
.برچسب‌همه
.برچسب‌همه جلسه‌ی امشب ساعت ۹
```
برای کاهشِ ریسکِ اسپم/محدودیتِ اکانت، اعضا در batchهای ۵تایی و با فاصله‌ی
چندثانیه‌ای بین هر پیام تگ می‌شن، و این دستور روی گروه‌های بزرگ‌تر از ۲۰۰ عضو
کار نمی‌کنه. ⚠️ این قابلیت رو با احتیاط و کم استفاده کن - استفاده‌ی مکرر
ممکنه توسط سیستم‌های ضداسپم تلگرام محدودیت ایجاد کنه.

## سرگرمی

چندتا دستور سرگرمی/بازی هم هست:
```
.تایپ‌زنده سلام دنیا      (افکت تایپ زنده حرف‌به‌حرف)
.پیش‌تایپ سلام            (شبیه‌سازی تایپ قبل از ارسال واقعی)
.معکوس سلام               (معکوس‌کردن متن)
.طنز متن شما               (حروف بزرگ‌وکوچکِ متناوب، طنزآمیز)
.تاس 4                    (تاس واقعی می‌ندازه تا عدد ۴ بیاد)
.شیرخط                    (شیر یا خط)
.تصادفی 1 100              (یه عدد تصادفی بین ۱ تا ۱۰۰)
.انتخاب پیتزا, برگر, سوشی  (انتخاب تصادفی بین چند گزینه - با کاما یا فاصله جدا کن)
.سنگ‌کاغذقیچی سنگ          (بازی سنگ‌کاغذقیچی با بات)
.اسلات                    (ماشین اسلات با سه نماد تصادفی)
.جادوگر فردا هوا خوبه؟     (پاسخ تصادفیِ توپ جادویی به سوال بله/خیری)
.عشق‌سنج علی و سارا         (درصد عشق‌سنجِ شوخی؛ برای یه جفتِ ثابت همیشه یکسانه)
.این‌یا‌اون                 (یه سوالِ «این یا اون» تصادفی)
```

**بازی حدسِ عدد:**
```
.حدس شروع        (یا .حدس شروع 500 برای بازه‌ی بزرگ‌تر - پیش‌فرض ۱ تا ۱۰۰)
.حدس 50          (حدس بزن - راهنمای بالاتر/پایین‌تر می‌ده)
.حدس لغو         (لغو بازیِ فعال)
```
هر چت یه بازیِ مستقل داره. توجه کن این بازی فقط توی حافظه نگه داشته می‌شه، پس
با ری‌استارت سرویس بازیِ در حال اجرا از بین می‌ره (که طبیعیه، چون یه سرگرمیِ
کوتاه‌مدته، نه بخشی از تنظیمات دائمی).

## فونت پیام

با `.قلم` می‌تونی متن رو به فونت‌های مختلف تبدیل کنی - هم به‌صورت یه‌بار، هم
به‌صورت خودکار روی همه‌ی پیام‌های عادی‌ای که می‌فرستی:
```
.قلم فهرست                 (لیست کامل با نمونه)
.قلم bold سلام Hello       (تبدیل یه‌بار)
.قلم تنظیم fa_kashida       (تنظیم فونت پیش‌فرض)
.قلم روشن                  (از این به بعد همه‌ی پیام‌هات خودکار فونت می‌شن)
.قلم خاموش                 (خاموش کردن حالت خودکار)
.قلم وضعیت                 (وضعیت فعلی)
```

سه دسته فونت داری (۲۷ مورد):
- **انگلیسی** (۱۰ فونت: `bold`, `italic`, `bold_italic`, `script`, `fraktur`,
  `sans_bold`, `monospace`, `smallcaps`, `circled`, `upside_down`) - از بلاک
  یونیکد Mathematical Alphanumeric Symbols، فقط روی حروف لاتین اثر می‌ذارن.
- **فارسی** (۱۳ فونت). سه‌تاشون واقعاً روی شکلِ رندرشده‌ی حروف اثر می‌ذارن، نه
  فقط دور متن دکوراسیون:
  - `fa_kashida` — کشیدگی واقعی با تطویل عربی (ـ)، دقیقاً همون تکنیک خوشنویسی
  - `fa_underline` — زیرخط واقعی زیر تک‌تک حروف
  - `fa_strike` — خط‌خوردگی واقعی روی تک‌تک حروف

  بقیه (`fa_spaced`, `fa_stars`, `fa_flowers`, `fa_brackets`, `fa_elegant`,
  `fa_ribbon`, `fa_diamond`, `fa_wave`, `fa_boxed`, `fa_hearts`) تزئینی‌ان.

  ⚠️ یه نکته‌ی صادقانه: یونیکد یه بلاک نایاب هم به اسم «Arabic Mathematical
  Alphabetic Symbols» داره که شبیه بولد/ایتالیک واقعی برای عربی/فارسیه، ولی
  پشتیبانی فونتش روی خیلی از گوشی‌ها ضعیفه (ممکنه باکس خالی نشون بده) و چون
  این محیط به اینترنت وصل نیست نتونستم نگاشت دقیق کدپوینت‌هاش رو تأیید کنم -
  به همین دلیل عمداً پیاده‌سازیش نکردم تا ریسک نمایش کاراکتر اشتباه نره بالا.
- **ترکیبی** (۴ فونت: `mix_bold`, `mix_italic`, `mix_script`, `mix_mono`) -
  حروف لاتین رو فونت می‌کنن و کل متن (فارسی+انگلیسی) رو با نماد تزئینی قاب
  می‌گیرن.

می‌تونی روی یه پیام ریپلای کنی و فقط `.قلم <نام>` بزنی، لازم نیست متن رو
دوباره تایپ کنی.

⚠️ **درباره‌ی حالت خودکار:** چون تلگرام پیام رو اول واقعی می‌فرسته و بعد ربات
ادیتش می‌کنه، یه لحظه‌ی خیلی کوتاه متنِ اصلی (بدون فونت) قابل‌دیدنه، بعد جایگزین
می‌شه. این محدودیت ذاتیِ همه‌ی سلف‌بات‌هاست، چون امکان تغییردادن پیام قبل از
ارسال واقعی وجود نداره. دستورهای خودِ ربات (هر چیزی که با `.` شروع بشه) از
فونت خودکار مستثنی‌ان، پس روشن‌بودنش باعث خراب‌شدن بقیه‌ی دستورها نمی‌شه.

## 📊 آمار سلف‌بات

با `.آمار` هر وقت خواستی می‌تونی ببینی سلف‌بات واقعاً چه وضعیتی داره:
```
.آمار         (خلاصه‌ی کلی: دستورات، پیام‌ها، ارسال‌خودکار، خطاها، زمان فعالیت + پراستفاده‌ترین دستورها و چت‌ها)
.آمار چت‌ها     (آمار کامل به‌تفکیک هر چت)
.آمار بازنشانی  (پاک‌کردن شمارنده‌ها و شروع از صفر)
```
دقت کن «تعداد خطاها» فقط خطاهای سیستمی/پس‌زمینه (مثل خطای شبکه یا API تلگرام)
رو می‌شمره، نه خطاهایی که خودت با ورودی اشتباه به یه دستور ایجاد می‌کنی (مثل
یه عبارت ریاضی نامعتبر توی `.حساب`).

آمار در PostgreSQL ذخیره می‌شه (هر ۶۰ ثانیه یک اسنپ‌شاتِ اتمیک) تا با
ری‌استارت/ری‌دیپلوی از دست نره.

## 💾 بکاپ‌گیری

با `.پشتیبان` چند جور بکاپ می‌تونی بگیری - همه به Saved Messages ارسال می‌شن:

```
.پشتیبان 200            (بکاپ متنیِ ۲۰۰ پیام آخر همین چت)
.پشتیبان json 200       (همون، ولی خروجی JSON ساختاریافته برای پردازش برنامه‌ای)
.پشتیبان رسانه 200      (دانلود و فوروارد فایل‌های رسانه‌ی ۲۰۰ پیام آخر)
.پشتیبان چت‌ها           (لیست کامل چت‌ها/گروه‌ها/کانال‌های اکانتت)
.پشتیبان تنظیمات        (بکاپ کامل تنظیمات بات: یادداشت، منشی، ارسال‌خودکار، فونت، ساعت، آمار)
```

سقف پیش‌فرض ۲۰۰۰ پیام برای بکاپ‌های متنی/JSON و ۵۰ فایل برای بکاپ رسانه‌ست -
برای جلوگیری از تایم‌اوت و محدودیت آپلود تلگرام.

**بکاپ تنظیمات به‌عنوان یک نسخه‌ی پشتیبانِ اضافی:** از این نسخه به بعد منبع
اصلیِ تنظیمات PostgreSQL است، پس با ری‌دیپلوی چیزی پاک نمی‌شه. با این حال
`.پشتیبان تنظیمات` / `.بازیابی` همچنان در دسترسن - مثلاً برای گرفتن یک
نسخه‌ی JSON قابل‌نگهداری قبل از تغییرات بزرگ، یا برای انتقال تنظیمات بین دو
دیتابیس/محیط:
```
.بازیابی
```
(با ریپلای روی فایل خروجیِ `.پشتیبان تنظیمات`) همه‌ی تنظیمات (یادداشت‌ها،
منشی، ارسال‌خودکار، فونت، ساعت) رو در PostgreSQL برمی‌گردونه سرجاشون.

## نکات امنیتی

- فایل `.env` یا Session String رو جایی منتشر نکن — معادل رمز اکانتته.
- دستورات مدیریتی گروه (`.اخراج` / `.مسدود` / `.ارتقا` / `.تنزل`) رو فقط توی
  گروه‌های خودت که ادمینشون هستی استفاده کن.
- فاصله `CLOCK_INTERVAL` رو خیلی کم نکن (زیر ۳۰ ثانیه) تا ریسک محدودیت از طرف
  تلگرام کم بمونه.
- فایل خروجیِ `.پشتیبان تنظیمات` رو جای امنی نگه دار: شامل رمز عبور یا Session
  نیست، ولی متن یادداشت‌ها و تنظیمات منشی/ارسال‌خودکارت توشه. `.بازیابی` فقط
  با ریپلای‌کردنِ خودتِ owner (پیام outgoing) کار می‌کنه، پس کسی جز خودت
  نمی‌تونه از راه دور تنظیماتت رو عوض کنه.
